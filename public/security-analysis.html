Security Analysis

1) How vulnerabilities could affect this login system

If SQL Injection existed in login queries, an attacker could bypass authentication or read user data. If broken authentication existed (weak password handling, predictable sessions), attackers could take over accounts. This would allow unauthorized access to protected pages and student activity.

2) What happens if security measures are not implemented

Without password hashing, leaked credentials would expose real passwords immediately. Without input validation, malicious payloads could reach backend logic and increase injection risk. Without safe error handling, attackers could learn system behavior (valid users, backend details) and craft targeted attacks.

3) How implemented features help prevent attacks

  • Hashed passwords (bcrypt): protects stored credentials even if data is leaked.
  • Input validation: rejects suspicious username/password formats before processing.
  • Generic login errors: prevents user enumeration and avoids exposing internals.
  • Session-based access control: protects the dashboard and lesson link after login only.
